# 自动转谱准确度与发布验收

2026-09-14。本文件记录实测问题、候选模型对比和下一阶段验收方案。**当前逐音转谱尚未达到正式发布标准；没有发布批准。** 页面添加 Beta 提示、接口测试通过、成功生成谱，都不能证明音乐内容正确。

## 已经定位的问题

用户录音 16–28 秒的第二段为去人声伴奏，第三段为现有 MusicXML 经 alphaTab / SONiVOX 演奏。针对同一段保存的识别结果：

- 五线谱/六线谱目前将起音和结束时间强制对齐到十六分音符。45 个片段内新起音相对原始模型时间平均移动 28.9 ms，最大约 58 ms。原始模型时间也有误差，不能当作真实演奏标注。
- 三个相隔约 70 ms 的估计拨弦被挤到同一时刻，破坏分解和弦的起音顺序。
- 谱面生成的 MIDI 在此片段所有力度均为 95。模型的 activation 不能直接当成实际拨弦力度或校准过的正确率。
- 模型输出的 pitch bend 没进入当前谱面演奏；同弦约束也会截断延音。谱面排版、指法建议和录音的演奏还原需要分开处理。
- alphaTab 实际播放的音高与生成谱一致，未发现全局八度偏移；差异不能归咎于一个播放器移调错误。

诊断证据位于 local verification artifacts (not included in the repository)。这些是数据和信号分析结论，没有声称已完成听感或逐音人工验收。

## 真实录音基准与候选比较

从 [GuitarSet 1.1.0](https://zenodo.org/records/3371780) 事先固定选择 12 段麦克风实录：6 位演奏者、5 种风格，每位各一段伴奏和 solo。共 1,534 个标注音符。文件选择规则、来源、CC-BY-4.0 归属和 SHA-256 写入 manifest。选择不依赖模型结果，也没有针对这些样本调阈值。

采用 mir_eval 一对一音符匹配：音高误差 ≤50 cents、起音误差 ≤50 ms；计入结束时间时，容差为 `max(50 ms, 标注时长的 20%)`。按所有片段合计计算 micro 指标，不通过时间平移或动态对齐美化成绩。

| 实测指标 | 当前 Basic Pitch 0.4.0 | GAPS 吉他候选模型 |
| --- | ---: | ---: |
| 音高 + 起音精确率 | 64.1% | 83.2% |
| 音高 + 起音召回率 | 81.0% | 86.8% |
| 音高 + 起音 F1 | 71.6% | 84.9% |
| 再计入结束时间的 F1 | 41.1% | 36.9% |
| 音高 + 起音匹配数 | 1,243 / 1,534 | 1,331 / 1,534 |
| 输出音符数 | 1,938 | 1,600 |

这里的未匹配音符也包括起音超出容差，不能全部解释成音高识别错误。F1 综合精确率与召回率，不能称为整首歌“还原百分比”。候选模型在起音上有明显收益，但时长指标退步，12 段中还有两段起音 F1 退步，因此没有直接替换产品默认模型。

候选来自作者发布的 [GAPS checkpoint](https://huggingface.co/xavriley/midi-transcription-models/blob/main/guitar-gaps.pth)，SHA-256 为 `65483e7c0e340a90415b15b520687587698c8c728f5fa470a205f13ee45c6513`。使用作者维护的 CRNN 推理代码、CPU 两线程和默认阈值，权重要求完整匹配，独立评测依赖没有安装进产品运行环境。相关 [GAPS 论文](https://arxiv.org/abs/2408.08653) 用于选择候选；以上数字均为本地实测，不是论文成绩。

限制：这是很小的内部回归集。Basic Pitch 的训练包含 GuitarSet；未确认候选 checkpoint 的全部训练样本，所以不是独立泛化验收。只有一类干净声学吉他的录音条件，未包含人声混音、失真电吉他或多人演奏。标注没有再经吉他手人工复核。上游已报告的三份错误标注不在本次选样中，但不能据此认定其余标注没有误差。

## 下一步按什么顺序解决

1. **先固定发布范围和真实验收集。** 高完成度的首个支持范围建议为单把清晰木吉他，分别覆盖单音、分解和弦和扫弦。吉他加人声单独评估；完整乐队、两把吉他和重失真不能从干净吉他的成绩推断可用。为每个准备开放的范围收集至少 30 段真实录音，由吉他手核对音高、起音、结束和重要奏法；按演奏者隔离开发集与发布验收集。用户这段失败录音进入开发集，尚缺人工核对的参考音符。
2. **升级逐音识别，同时修结束时间。** 将 GAPS 作为候选，与现有模型在相同未见样本上比较。记录每类输入的错漏音、起音、时长及耗时，不用总体均分掩盖扫弦失败。针对泛音假音和延音截断开发音频证据约束；阈值和融合策略只在开发集调整，冻结后再跑验收集。不能用和弦理论补出原录音里没有弹的音。
3. **减少播放和制谱阶段的信息损失。** 保存独立的原始演奏时间线，并与谱面音符建立对应；谱面可以量化以便阅读，演奏还原保留未量化的起音、结束和拨弦顺序。谱面播放与原时序回放需明确区分。力度和推弦需要独立校准，不直接把模型 activation 当作真实力度。先测音符和节奏正确，再改善音源、共鸣和技巧音色。
4. **逐阶段验证人声分离。** 对同一段已标注真实吉他，分别评估原音、去人声、吉他独立轨。分离必须减少干扰且不丢主旋律/弱音；不能因为人声更小就认定转谱更准。最终用含真实歌唱的样本验收，合成吉他加 TTS 的测试只保留作流程回归。
5. **验收用户实际拿到的结果。** 对同一段原音、分离音轨和模拟演奏匹配响度与时间，做随机顺序听评，并核对最终导出的谱。至少覆盖主旋律、低音线、和弦换位、拨弦顺序、休止和延音；用户不应需要逐小节重扒才能使用。

## 建议的发布门槛

以下是待验证的产品目标，不是已达到的结果，也不是行业统一标准。

- 每个正式支持的输入类别，在独立、人工核对的验收集上，音高 + 起音精确率和召回率均至少 95%；同时检查最差样本，不能只报平均数。
- 再计入结束时间的 F1 至少 85%，并经人工检查重要的低音延音、休止和连奏，防止指标通过但音乐仍不对。
- 至少两名会弹吉他的人按固定表格独立审核；主旋律、和弦切换及节奏无明显错误，单段不能依赖大量人工重写。
- 同步播放、速度切换、循环、修改和导出均验证同一批真实样本；修改不能在重新分析或导出时丢失。
- 公布能力范围和实测方法；未支持的录音可提示重新录制或进入研究模式，不能以完整谱面外观暗示结果准确。

如果此次 launch 的核心承诺是准确逐音转谱，建议等这些要求通过再发布该功能。介绍页或已经单独验收的练习功能可以独立准备；本次没有改动发布范围或执行上线。

## 可复跑的工具

```sh
.venv-audio/bin/python scripts/fetch_guitarset_regression.py
.venv-audio/bin/python scripts/benchmark_transcription.py \
  verification/transcription-quality/manifest.json \
  --output verification/transcription-quality/basic-pitch-baseline

# 使用候选引擎产生的同一批 JSON 音符，复用完全相同的评价器
.venv-audio/bin/python scripts/benchmark_transcription.py \
  verification/transcription-quality/manifest.json \
  --predictions verification/transcription-quality/gaps-predictions \
  --engine-label 'GAPS guitar-gaps.pth / upstream default thresholds' \
  --output verification/transcription-quality/gaps-evaluation

.venv-audio/bin/python -m pytest tests/test_transcription_benchmark.py -q
```

候选推理脚本为 `scripts/evaluate_gaps.py`，需要本次已准备的 `verification/transcription-quality/piano-inference/`、`eval-deps/torchlibrosa` 和已校验 checkpoint。精确源码 commit、参数、推理耗时记录在 `gaps-predictions/provenance.json`。这些是隔离的本地实验资产，尚未提供产品安装器。

原始与候选的逐段输出、完整报告均位于 `verification/transcription-quality/`。评价器的三项检查覆盖重复/错音/漏音、一对一匹配、起音与时长分开计分及空输出，已通过。通过这些检查只代表评价工具逻辑符合预期，不批准产品发布。
