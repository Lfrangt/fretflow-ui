# 单音、双音与延音复核

2026-09-14。本轮接入的是可检查的起音分组和编辑入口，尚未实现可靠的自动真假双音判决。

## 已接入页面

音频播放器下新增“单音与双音复核”，支持逐段回听、重叠音筛选、分页和跳到对应音符编辑。修改或删除音符后，分组随结果重新计算，已有演奏 MIDI 与谱面也使用同一份可编辑结果。

`lib/note-attacks.ts` 按估计起音分组，采用距每组最早起音 40 ms 的固定窗口，避免把连续分解和弦链式合并成一个大组。两个不同音高的同组候选标为“双音候选”；之前起音但仍在持续的音单列，不计为本次拨弦。两个同音高检测单列“同音重叠”，不能仅凭音频事件确定弹了几根弦。

八度、十二度、双八度关系仅标为泛音疑点。真实八度双音和自然泛音奏法不能凭音程自动删除。快速分解、扫弦和模型起音误差会使固定窗口分组不等同于实际奏法，因此所有标签均为候选或估计。

用户原记录 `a8cf2112a5cf4397b6483272e4e5a626` 前 12 秒的重点位置包括：1.9621 秒 C4/C5，3.9138/3.9487 秒 A#3/A#4，7.7361 秒 A#3/A#4，10.676 秒 B3/B4。GAPS 候选没有在这些位置输出相应高八度起音；这属于模型分歧，不是人工核实的假音标签。初版复核入口没有修改音符；2026-09-15 的局部试听修订如下。

## 2026-09-15：用户指出片段的实际回放修订

用户指出 42 秒对比视频最后 10 秒刚开始出现假双音和赶拍。视频第 32.55 秒附近对应源录音 3.9138 秒：A#3 后仅 34.9 ms 又触发 A#4。原回放只修正制谱量化时序，仍照着错误检测结果播放，复核入口本身没有改善声音。

这次通过现有带 revision 校验的音符编辑 API，保存了源录音 **3.3–8.3 秒**的局部试听修订，记录从 revision 0 到 10：排除 8 个额外候选起音，合并一次 F3 延音，将一次迟到的 G2 起音从 4.9484 秒改为第二模型的 4.8886018 秒。其余 573 个音符逐字段保持不变，不修改速度、音高或全曲复音策略。

这是结合用户对这段单音拨弦的反馈、GAPS 独立候选和原声起音包络制作的试听稿，不是自动校正算法。8.1437 秒短 C4 是否实际存在仍未确认，在本次试听稿中暂时排除；结束时间也未经吉他手逐音核实。其他片段原有识别错误仍可能存在。

本地证据在 `verification/passage-correction/`：

- `before.json` 保存 revision 0 完整原结果，`applied.json` 保存修订结果；`review.json` 逐项记录理由和来源哈希。
- `apply.py --undo` 可通过现有编辑接口恢复原始音乐字段；保留编辑历史，遇到冲突停止。
- `render.mjs` 使用当前产品的 `buildPerformanceMidi` 和同一 FreePats 纯古典吉他音色，离线生成前后音频；不是浏览器录屏。
- `original-previous-corrected.wav` 顺序为原视频原声、旧回放、修订回放，每段 5 秒，间隔 0.65 秒。仅作固定增益音量匹配和裁剪边缘 5 ms 淡化，没有变速或改调。
- 三段音频解码通过、无削波；修订片段的音符触发数从 18 降为 10，间隔 0.4644–0.4992 秒。现有 12 项起音分组及演奏 MIDI 测试通过，更新后谱面 XML 解析通过。

本轮没有可用的音频感知工具，`listening_review=false`；音符计数、波形检查和正常解码不能替代听觉验收，不能据此宣布可发布。

## 第二声校正实验与未启用原因

`backend/note_texture.py` 使用两份逐音结果做逐音高、一对一的起音匹配：

- 第二模型也检测到独立起音时，保留真实双音候选，包括八度。
- 缺少独立起音支持、与低音成谐波关系且激活较弱的高音，只提出排除建议。
- 相邻同音片段、另一个音被拨动、第二模型仍判为原音延续时，只提出合并延音建议。
- 人工编辑优先；原结果在 `notes` 中保持不变，实验修改在 `proposed_notes` 中单独返回。没有最大同时发声数限制。

使用已存在的 GuitarSet 18 段回归集、2,390 个参考音符验证，固定音高 50 cents、起音 50 ms、一对一匹配：222 个排除建议中，215 个原本未匹配参考音符，7 个原本匹配。其中有 6 个属于参考中同时起音的多音事件。因此即使总体起音 F1 从 74.28% 提升至 77.23%，该自动删音规则仍未通过保留真实双音的要求，**未接入默认识别或回放**。

这里的“未匹配参考”也可能来自时间偏差或标注问题，不能直接称作已确认假音；预训练可能接触 GuitarSet，此回归集不是独立泛化准确率。

证据：`verification/note-texture/regression-report.json`、`decisions.json`、`user-review.json` 和 `evaluate.py`。实际用户片段上额外验证了关闭 Basic Pitch 的 melodia 后处理仍会保留 1.962 秒 C5，因此仅关掉残余能量补音不足以解决。

## 验证

- Python 全套 43 项通过，包括真实八度双音保护、已有延音、重复拨弦、保留人工修改及实验输出不改原结果。
- Node 全套 17 项通过，包括单次拨弦叠加延音、双音候选、同音重叠、分解和弦不链式合并、音符修改/排除与纯吉他回放。
- TypeScript 检查通过。浏览器用真实用户记录验证复核入口、回听和音符编辑跳转。

下一步需要针对单音、真实双音（含八度）、分解和弦、连续同音、自然泛音分别制作有独立轨道或人工复核的验收数据；不能只优化一个总体 F1 就认为双音问题已经解决。
